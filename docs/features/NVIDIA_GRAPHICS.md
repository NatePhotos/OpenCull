# NVIDIA graphics rendering

Uses the native graphics stack for webview compositing, photo transformations, WebGL and supported 2D canvas rendering. It does not implement CUDA image decoding or change ONNX inference. WebKit still decides which operations are accelerated.

Linux: `npm run desktop -- --nvidia` requests hardware compositing, enables WebGL and supported accelerated canvas, and removes inherited software/compositing-disable overrides before GTK initializes. It uses `WEBKIT_DMABUF_RENDERER_FORCE_SHM=1` and `WEBKIT_DMABUF_RENDERER_DISABLE_GBM=1` rather than disabling the DMA-BUF renderer and prefers XWayland when an X display is available and no backend was explicitly requested, because direct DMA-BUF/GBM presentation failed with this test machine’s proprietary driver. This leaves accelerated compositing enabled while changing buffer transport. A native CSS-only animation probe on this RTX 3060 Ti allocated 53 MiB in the WebKit graphics process; no WebGL probe was needed to produce that allocation. `npm run desktop -- --compatibility` retains the DMA-BUF workaround; `npm run desktop -- --software` explicitly requests a software path for comparison. The ordinary desktop command remains automatic and changes no environment flags. Packaged binaries accept `--graphics=nvidia`, `--graphics=compatibility`, `--graphics=software`, or `OPENCULL_GRAPHICS`. Linux-only code and dependencies leave macOS/Windows native rendering unchanged.

Settings → Storage → Graphics acceleration provides a renderer probe. An NVIDIA WebGL renderer is evidence for that context, not proof that every rendering operation is GPU accelerated. Verify native WebKit process GPU device use and frame timings as well. These profiles do not install drivers or edit system configuration. On hybrid systems, choose the discrete GPU through the system's normal offload launcher.

Reference: https://docs.webkit.org/Ports/WebKitGTK%20and%20WPE%20WebKit/Graphics.html and the WebKitGTK HardwareAccelerationPolicy API. The NVIDIA profile requests Always; it does not claim a specific performance improvement. Compatibility remains available for driver/compositor issues.

## WebKitGTK 2.54 repaint workaround

The Linux NVIDIA profile also defaults `WEBKIT_USE_SKIA_FOR_COMPOSITION=0` before WebKit starts. This selects WebKit's fallback compositor while retaining hardware compositing. An explicit value supplied by the launcher is preserved; `WEBKIT_USE_SKIA_FOR_COMPOSITION=1 npm run desktop -- --nvidia` allows comparing the newer compositor again. Other profiles and macOS/Windows do not receive this default.

On the tested RTX 3060 Ti / NVIDIA 615.78.08 / WebKitGTK 2.54.1 / Hyprland system, photo zoom and Settings interactions briefly displayed previous frames. Software rendering, native Wayland rendering, and disabling animations/blur did not resolve the reported flicker. A plain WebKit control window stayed stable. Switching the full app to the fallback compositor removed the flicker in the user's comparison; `nvidia-smi pmon` still showed its WebKit process using the GPU. This is a tested compatibility workaround for that combination, not proof of a universal driver fault or a performance improvement.

Settings → Storage → Check renderer reports whether the fallback was requested. Restart the desktop after changing launch environment variables. No photo files or saved interface preferences need changing.

WebKit describes the new compositor and changes to the software rendering path in its [2.54 release notes](https://webkitgtk.org/2026/09/16/webkitgtk-2.54-highlights.html). Its [2.54 startup implementation](https://github.com/WebKit/WebKit/blob/webkitglib/2.54/Source/WebKit/WebProcess/WebPage/CoordinatedGraphics/DrawingAreaCoordinatedGraphicsGLib.cpp) handles the compositor override.

On Linux, Auto now selects the NVIDIA profile when the primary boot display device is bound to the NVIDIA driver and X11 is available. Secondary/offload-only NVIDIA GPUs do not trigger this choice. Explicit profiles and GDK_BACKEND overrides are preserved. Other GPUs and macOS/Windows retain their defaults. Renderer diagnostics report both the requested and active profiles. This avoids the fatal Wayland protocol error observed with the default desktop command on the tested NVIDIA system.
